# Contributing to WFlow-REA

First off, thank you for considering contributing to **WFlow-REA**! It's people like you that make open-source tools great.

**🚧 Note: WFlow-REA is still in active development.**
*The codebase, features, and architecture are actively evolving. If you are planning a major structural change or a large feature, please open an issue to discuss it with the maintainers first so we can ensure it aligns with the current roadmap!*

The following is a set of guidelines for contributing to WFlow-REA. These are mostly guidelines, not rules. Use your best judgment, and feel free to propose changes to this document in a pull request.

## How Can I Contribute?

### Reporting Bugs
This section guides you through submitting a bug report. Following these guidelines helps maintainers understand your report, reproduce the behavior, and find related reports.

* **Check existing issues:** Before creating bug reports, please check a list of existing issues as you might find out that you don't need to create one.
* **Use a clear title:** Explain the problem and include additional details to help maintainers reproduce the problem.
* **Describe the steps to reproduce:** Be as specific as possible.
* **Describe the behavior you observed after following the steps:** What actually happened?
* **Explain which behavior you expected to see instead and why.**

### Suggesting Enhancements
Enhancement suggestions are tracked as GitHub issues. 

* **Use a clear and descriptive title** for the issue to identify the suggestion.
* **Provide a step-by-step description of the suggested enhancement** in as many details as possible.
* **Explain why this enhancement would be useful** to most WFlow-REA users.

### Pull Requests
The process described here has several goals:
- Maintain WFlow-REA's quality.
- Fix problems that are important to users.
- Engage the community in working toward the best possible WFlow-REA.

Please follow these steps to have your contribution considered by the maintainers:

1. **Fork the repo** and create your branch from `main`.
2. **Clone your fork locally:**
   ```bash
   git clone https://github.com/YOUR-USERNAME/WFlow-REA.git
   ```
3. **Set up the development environment:** Install the necessary dependencies (refer to the README for specific installation steps).
4. **Make your changes:** Keep your commits focused and modular.
5. **Test your changes:** Ensure that your code does not break existing functionality. 
6. **Update the documentation:** If you are adding a new feature or changing an existing one, please update the README or relevant documentation.
7. **Issue that pull request!** Ensure the PR title clearly describes the changes. 

## Styleguides

### Git Commit Messages
* Use the present tense ("Add feature" not "Added feature").
* Use the imperative mood ("Move cursor to..." not "Moves cursor to...").
* Limit the first line to 72 characters or less.
* Reference issues and pull requests liberally after the first line.

## Need Help?
If you have any questions about the contribution process, feel free to reach out by opening a discussion or an issue. 

Thank you for helping us build WFlow-REA!
